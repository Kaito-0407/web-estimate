CLAUDE.mdの書き方｜公式の推奨ルールと置き場所、テンプレート

結論：CLAUDE.mdには「毎回守ってほしい事実とルール」だけを、確かめられる形で、200行未満に書きます。迷ったら /init で下書きを作り、Claudeが自分では気づけないことを足していきます。

CLAUDE.mdとは

Claude Codeがセッションの開始時に毎回読み込む指示ファイルです。ビルドやテストのコマンド、書き方の決まり、フォルダ構成など、毎回伝えたいことを書いておくと、同じ説明を繰り返さずに済みます。

何を書くか

公式ドキュメントでは「毎回のセッションで必要な事実」を書くよう勧めています。例として挙げられているのは次のものです。

  • ビルドのコマンド
  • コードの書き方の決まり
  • プロジェクトの構成
  • 「必ず〜する」というルール

手順の長い作業や、一部のフォルダでしか使わない決まりは、スキルや .claude/rules/ に分けるよう書かれています。

公式の推奨ルール3つ

1. 具体的に書く

公式の例：

  • 「コードをきちんと整形する」ではなく「インデントは2スペース」
  • 「変更をテストする」ではなく「コミット前に npm test を実行する」
  • 「ファイルを整理する」ではなく「APIのハンドラーは src/api/handlers/ に置く」

2. 200行未満を目安にする

長いほど読み込む量が増え、指示が守られにくくなると説明されています。@ で別ファイルを読み込んでも、読み込まれた分は同じく数えられるので、短くする効果はありません。

3. 見出しと箇条書きで整理し、矛盾をなくす

関連する指示を見出しの下に箇条書きでまとめます。2つの指示が食い違うと、Claudeがどちらかを適当に選ぶことがあるため、定期的に見直します。/doctor prompt-audit で点検もできます。

置き場所

場所用途共有範囲
./CLAUDE.md または ./.claude/CLAUDE.mdプロジェクトの決まりチーム（Gitで共有）
./CLAUDE.local.md自分だけの設定（.gitignoreに追加）自分だけ（このプロジェクト）
~/.claude/CLAUDE.mdすべてのプロジェクトで使う自分の好み自分だけ（全プロジェクト）

長くなったら .claude/rules/ に分ける

テーマごとのファイル（例：testing.md）に分けられます。先頭に paths を書くと、その種類のファイルを扱うときだけ読み込まれます。

---
paths:
  - "src/api/**/*.ts"
---

# 予約管理アプリ

Next.js と Supabase で作る社内向けの予約管理アプリ

## コマンド
- 開発サーバー: `npm run dev`
- テスト: `npm test`
- Lint・整形: `npm run lint`

## ディレクトリ
- src/app/ はページ、src/lib/ は共通処理

## ルール
- インデントは2スペース
- コンポーネント名は PascalCase

## してはいけないこと
- main ブランチへ直接 push しない

## 完了の条件
- 変更したら `npm test` を実行し、通ってから完了と報告する
